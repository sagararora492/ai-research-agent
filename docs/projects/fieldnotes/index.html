The problem

An answer needs
a trail.

A useful research brief needs more than fluent text. Readers need to inspect the source passages, understand the scope of the search, and see what remains unknown.

Fieldnotes explores that workflow end to end: plan the research, collect evidence, produce findings, and preserve the sources. It can work with local documents, search the web through Tavily, or use configured model providers to synthesize results.

The offline workflow uses Python’s standard library and runs without API keys. Live search and model synthesis are optional.

S1 · Sample interview notes

DEMONSTRATION DATA, NOT REAL RESEARCH. In this fictional research assistant pilot, product analysts need to compare documents, preserve citations, and share research briefs. The primary user need is traceability: a reader should be able to inspect the source passage behind each finding. Success metrics include time to a reviewed brief and the fraction of findings with supporting citations. Operational constraints include limited API budgets and sensitive internal documents.

S2 · Sample evaluation notes

The fictional team compared manual search, a generic chatbot, and a research assistant with source storage. Adoption depended on reviewers understanding where claims came from; no quantitative time savings were measured.

S3 · Sample design review

The fictional review identifies provider outages, stale snippets, duplicate sources, and unsupported synthesis as risks. Proposed opportunities include bounded search budgets, local document research, citation validation, and explicit evidence gaps.

Engineering choices

Designed around the evidence.

01 / FLEXIBILITY

Configurable agents

Assign research focuses and model profiles to agents. Bound concurrent work and search budgets, and keep execution traces for review.

02 / FAILURE HANDLING

Explicit fallbacks

Provider failures and invalid citations produce visible warnings. Depending on configuration, retain extracted evidence or fail the session.

03 / REPRODUCIBILITY

Runnable offline

Try the core workflow with sample documents and no credentials. The repository’s CI checks the application on Python 3.12 and 3.13.

Tradeoffs & next steps

What this
doesn’t prove.

Citation checks establish text correspondence, not truth. A passage can appear in a source and still be wrong, incomplete, or irrelevant. Human review remains necessary.

This is a bounded workflow: agents analyze retrieved evidence rather than choosing arbitrary tools or executing code. Adding agents can increase provider cost; concurrency limits do not cap total spending.

The web studio currently runs locally for a single user. This public page is a showcase. A hosted research service would need authentication, abuse controls, and deployment hardening.

Useful next experiments include a reviewed evaluation dataset, stronger relevance assessment, and measured comparisons of different agent configurations.
